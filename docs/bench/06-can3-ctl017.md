# 06 CAN3 to the CTL-017 on the NUCLEO-G474RE: heartbeat, homing without load

**Proves:** CAN3 runs at 500 kbit/s, the CTL-017 (node 0x10) boots, sends its heartbeat and status,
accepts the NMT start, refuses motion without the core heartbeat, homes with an unloaded motor,
stops on STOP, and stops by itself with fault F07 when the command keep-alive or the core
heartbeat goes missing.
**Moves the lift motor?** **Yes, from step 6**, unloaded: **no lift, no robot, no arms, no person
near the motor.** Two people.

> **Firmware status: [pending upperbody-fw #15/#16].** The CTL-017 firmware and its object dictionary are
> drafts (openamr-upperbody-fw #15 is the dictionary, #16 the firmware stacked on it), "host-tested
> and cross-compiled, never run on hardware". The values and frame layouts below are the proposal.
> The hardwired E-stop removes lift motor power independently of CAN3; CAN3 carries no safety function.
> This week there is **no integrated E-stop**: the motor supply switch is the stop.

Frame summary (node 0x10, classic CAN, 500 kbit/s; from the #15/#16 drafts, `TODO(Evans)` to confirm):

| Frame | COB-ID | Direction | Content |
|---|---|---|---|
| NMT command | 0x000 | host to node | `01 10` = start node 0x10; `80 10` = pre-operational; `02 10` = stop |
| Heartbeat | 0x710 | node to host | 1 byte NMT state (0x7F pre-op, 0x05 operational), every 100 ms |
| Core heartbeat | 0x701 | host to node | `05` every 100 ms, consumed with a 300 ms timeout |
| RPDO1 command | 0x210 | host to node | 3 bytes: seq, op (0 STOP, 1 MOVE_TO_STOP, 2 CLEAR_FAULT, 3 START_HOMING), stop id (0 to 2). Send again every 100 ms: the repeat is the keep-alive. |
| TPDO1 status | 0x190 | node to host | state, flags, position u16 (0.1 mm, 0xFFFF unknown), active stop id (0xFF none), last seq, cmd result, status counter |
| TPDO2 status | 0x290 | node to host | inputs (bits 0 to 2: three stop sensors L1000, L1175, L1350; bit 3 second E-stop; bit 4 Hall supply good), target stop, motor current mA, velocity, faults, aux flags |
| EMCY | 0x090 | node to host | fault event, byte 3 carries the fault number |

States in TPDO1 byte 0: 0 INIT, 1 UNHOMED, 2 HOMING, 3 IDLE, 4 MOVING, 5 STOPPING, 6 FAULT.
Faults F01 to F09: F02 Hall window or direction or sensor cross-check, F03 stall or over-current,
F04 travel timeout, F05 Hall supply lost while moving, F07 command or core heartbeat lost, F08 standstill
not confirmed, F09 two stop sensors active. In the fault mask, fault n is bit n minus 1 (F07 is 0x40).

The commands below were all run against the CTL-017 emulator (`tools/can_sil/ctl017_emulator.py`) on
`vcan` with can-utils, and the quoted outputs come from that run. Real hardware may differ.

  (NPN NO) or stand-ins. Board and shield revision: `TODO(Arka)`.

  is a lift, not a bench item; the bench motor for the BLDC shield is `TODO(Evans)`) and its supply
  voltage and current limit (the lift takes up to 7 A at 24 V in the robot, P-03 item 21): `TODO(Evans)`. Set the supply
  current limit **low** for the first run and raise it only with the owner.
- Stop sensors: the real sensors with a metal target on a rail, or three switches wired to the three
  inputs as stand-ins (NPN NO, active when the target is in front). Their positions
  (`TODO(Evans)` physical, the proposal has 5, 180 and 355 mm above the lower end) matter only for a real column.
- Only the CTL-017 on CAN3 in this procedure; the NUCLEO-H723ZG is **not** connected, the PC adapter is the master that plays the role of the base controller (core): it sends the NMT start,
  the heartbeat 0x701 and the commands. One master at a time.
- Termination: the CTL-017 end has the SN65HVD230 board termination or not (`TODO(Evans)`); PC adapter end as
  the adapter says. Check with `tools/bench/termination_check.md` for CAN3 (power off): 55 to 65 ohm.
- Interface: `sudo tools/bench/can_up.sh can3 500000`, then `ip -details link show can3`.

## Step 1. Power on, boot-up and heartbeat

```
candump -L can3 > $(date +%F)-can3-boot.log &
```
Power the G474 (USB) and the shield supply (motor supply **off**). Expected: a boot-up frame
`710#00` and then the heartbeat `710#7F` every 100 ms (pre-operational). Then:

```
python3 tools/bench/nmt_scan.py can3 --expect 0x10 --expect-period-ms 100
```

Expected (emulator output):
```
node 0x10 heartbeats=20 nmt=0x7F period=103 ms 1000h=0x00000000
PASS
```
Pass: node 0x10 heard, period 100 ms within 20 percent, answers the SDO read of 1000h. Record the 1000h value
(device type; the proposal has 0 in the emulator, the real value `TODO(Evans)`). Also read the identity
(1018h) if the SDO client is at hand; product code 17 is the proposal.

Check also: NMT state 0x7F (pre-operational) until started. Status frames **do not** appear in
pre-operational (PDOs run only in OPERATIONAL): `grep ' 190#' file.log` is empty. Pass.

## Step 2. NMT start and the first status

```
candump -L can3 > $(date +%F)-can3-run.log &
cansend can3 000#0110
sleep 1
grep ' 190#\| 290#' $(date +%F)-can3-run.log | tail -2
```

Expected (emulator, an unhomed start between two stops):
`190#01C0FFFFFF00FF06` and `290#10FF...`. Read TPDO1 as: state 01 (UNHOMED), flags `C0` (bit 6 motor
power, bit 7 recovery required: not homed), position `FFFF` (unknown), stop `FF` (none), last seq 00, result `FF`, counter. If a
stop sensor is active at power-up and only one, the node starts in IDLE with a valid position
(P-03 item 24): record which case you have (`flags` bit 0 is position valid).
The heartbeat now reads `710#05`. Two sensors active (or both end switches) at power-up must give FAULT,
never IDLE: test it once by activating two stand-in sensors before power-up, then removing one and
power cycling.

Pass: operational heartbeat, status frames every 100 ms with a counter that increments by one per
frame (check `status counter`, the last byte of TPDO1, in the log: consecutive values differ by 1, modulo 256).

## Step 3. Stop sensors and outputs, no motion

With the motor supply **off**, move the target in front of each sensor (or close each switch) and read
TPDO2 byte 0: bit 0 for L1000, bit 1 for L1175, bit 2 for L1350. Pass: each sensor sets exactly its
own bit and clears when the target leaves; a broken wire reads "not active" (test by unplugging a sensor:
bit clears; the lift would then rely on the Hall count and the timeouts).
Head light and Getac enable (RPDO2 `0x310`: head light on, dim level 0 to 100, Getac enable). Check with a meter or LED on the outputs:

```
cansend can3 310#010000     # head light on, dim 0 ... confirm the byte meaning, TODO(Evans)
cansend can3 310#000000     # off
```

The byte layout is from the emulator's header and is `TODO(Evans)` for the real firmware. Aux flags in TPDO2 byte 7 (bit 1 light, bit 2 Getac) must
follow the outputs. These outputs are low-side switches (head light) and a power enable (Getac):
measure the output with a meter, do not connect the real Getac or the real head light this week.

## Step 4. Motion is refused without the core heartbeat

Without sending 0x701, ask for homing (the motor supply is still **off**):

```
cansend can3 210#010300
sleep 0.5
grep ' 190#' $(date +%F)-can3-run.log | tail -1
```

Expected from the design note of #16: the command is **refused**, with a command result that says
heartbeat not fresh (result 12 in the note; the emulator numbers its results 0 to 11, so the number is
`TODO(Evans)`), and the state does not leave UNHOMED. STOP and CLEAR_FAULT are always processed.

> Observed on the emulator: with no core heartbeat ever sent, START_HOMING (`210#010300`) was
> **accepted** (state 2, HOMING) and, because the frame was not repeated, the node raised F07
> (fault mask `0x0040`, EMCY `090#07FF910740000000`, state 6) about 300 ms after the last command frame.
> In the emulator the core heartbeat is only monitored after the first heartbeat has been seen. That
> differs from the design note ("refused unless the core heartbeat is fresh"). On the real node,
> record which of the two you see and report it to Evans: a command that is accepted and then
> faulted is a different state history from one that is refused.

Clear any fault before continuing: send CLEAR_FAULT with a new seq, for example `cansend can3 210#050200` (seq 5, op 2, stop 0; with the conditions gone), or power-cycle the node.

## Step 5. Core heartbeat and keep-alive generator

The core side is played from the PC. Two generators with `cangen` (one bus, two background jobs):

```
cangen can3 -I 701 -L 1 -D 05 -g 100 &              # core heartbeat every 100 ms (gap in ms)
cangen can3 -I 210 -L 3 -D 010300 -g 100 &          # RPDO1 repeated every 100 ms: seq 1, START_HOMING
```

Stop both with `kill %1 %2` (or `pkill cangen`). Note the **seq byte**: the node treats the same RPDO1 repeated as the
keep-alive and a different seq with another op as a new command; `cangen` repeats one fixed
payload, which is exactly the keep-alive. A different command is sent with `cansend`, with a new seq.

## Step 6. Homing without load **(moves the lift motor, unloaded)**

Two-person checkpoint: motor free, nobody near it, supply switch in hand, current limit low, target
or stand-in sensors in place. Then, with the node operational (step 2) and the generators of step 5:

1. Motor supply on. Expected: TPDO1 flags bit 6 (motor power, 0x40) set.
2. Start the 701 generator, then the command generator `210#010300` (START_HOMING).
3. Expected (emulator): TPDO1 state 02 (HOMING), flags `C4` (motor power, recovery required, moving);
   the position runs down (a rate of about 9 mm/s homing speed in the emulator). On the real
   node: the motor turns slowly in the **down** direction (D10: home down); the Hall count changes (TPDO2
   velocity not zero), the motor current is plausible (TPDO2 mA; limit `TODO(Evans)`).
4. The first stop sensor reached sets the reference; the proposal continues to L1000, the lowest stop. Each sensor on the way cross-checks the Hall count. On the bench without
   a column, bring the target to each sensor in turn at the pace of the motor (or just L1000 for the first run).
5. End of homing: state 03 (IDLE), flags with position valid and no recovery flag, `stop` field = 0.
   Record the Hall count at each sensor and compare with the proposal positions (`TODO(Evans)`).

If the motor has no motion feedback (Hall unplugged) or no target is presented, **the node must fault by
itself**: stall (F03) after the stall time and travel timeout (F04), and switch the bridge off. Test that
once on purpose: homing with the target never presented; expected FAULT within the timeout (`TODO(Evans)`
value). Do not help it.

Pass: homing ends in IDLE with a valid position, or ends in the right fault for the deliberate failure;
the motor never runs after a fault. Record the time homing took, the current, the Hall counts.

## Step 7. STOP, keep-alive loss, core heartbeat loss

Each from a running move (homing or a MOVE_TO_STOP with a new seq, for example `210#020101` (seq 2, op 1, stop 1)):

| Test | How | Expected |
|---|---|---|
| STOP | `cansend can3 210#060000` (new seq 6, op 0) | STOPPING then IDLE or UNHOMED, no fault, motor off |
| Keep-alive loss | kill the 210 generator, leave 701 running | within 300 ms: FAULT, F07 (mask 0x0040), motor off, EMCY frame `090#...` with fault number 7 |
| Core heartbeat loss | kill the 701 generator, leave 210 running | within 300 ms: FAULT, F07, motor off |
| NMT leaves OPERATIONAL | `cansend can3 000#8010` | stop, target discarded, no fault |
| Motor supply off during a move | switch the supply off | stop, no fault, a new move is refused (result for no motor power); position keeps counting |
| Node power cycle | cycle the G474 supply | node restarts in UNHOMED, **no motion without a new homing**, no automatic resume |

Emulator check of the keep-alive row: a command stream stopped after `210#010300` produced
FAULT with fault mask `0x0040`; STOP `210#030000` after a fault was processed (state stayed FAULT, last seq updated).
Measure the time from the last 210 frame in the log to the motor off (scope on the H-bridge enable or the
Hall rate to zero) and the time of the EMCY frame. Pass: within 300 ms plus the stopping time
(`TODO(Evans)` limit). After each fault, send CLEAR_FAULT and check that **the lift does not move by itself**:
only a new command moves it (no automatic resume after any stop, fault or power loss).

## Pass criteria

- Steps 1 to 3 pass (heartbeat, start, sensors).
- Step 4 recorded (refused or accepted, with the result byte).
- Step 6: homing ends in IDLE with a valid position, deliberate failure ends in FAULT.
- Step 7: each row as expected; keep-alive and heartbeat loss within 300 ms.

## Stop condition

The motor runs with no command, runs after a fault, or runs in the wrong direction at homing: cut the motor
supply, record, stop. A current at the limit for more than a second: switch off.
